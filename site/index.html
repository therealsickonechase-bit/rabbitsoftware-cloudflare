RabbitOS

RabbitOS is the account-free workspace at app.rabbitsoftware.io. Open it in your browser with no email, password or CAPTCHA. Opening it does not install software or connect your files, vault or devices.

  • Public researchBrowse research records with their source links, then ask the hosted Qwen model about them. Your chats and notes stay in this browser.
  • Open dataSearch, sort and download research and ledger data as JSON or CSV, or read it from a command line.
  • Verifiable ledgerA hash-chained public log of changes that anyone can check in their own browser.
  • Brain and body explorerA 3D brain and body with research connected to it. Live signals stay on your own computer.

01 / SYSTEM

A research system with visible boundaries.

RabbitSoftware connects public-source research, local analysis, signed records, and experimental runtimes without pretending they are one thing.

Research pipeline

Retrieve public records, preserve their source identifiers, index them locally, and produce answers with citations.

  • PubMed
  • Europe PMC
  • ClinicalTrials.gov
  • ClinVar
  • NIH RePORTER
  • arXiv

Signed provenance

Nodes keep their own signed chains and replicate a research ledger. Validators reject events that contain personal data.

Separate applications

The hosted console, local Python backend, monitor, and research stack have separate setup and data boundaries. Local installation does not replace the host OS or automatically connect a private vault.

02 / DATA BOUNDARIES

Your device is the default boundary.

  • ALocal tools stay local. Selected-file viewing and local Ollama chat stay on your computer. RabbitOS notes and settings stay in your browser; public feeds and hosted Qwen require internet. It is not a synced offline vault.
  • BChoose before sending. Hosted Research AI and live public searches need consent. Local chat never falls back to hosted AI, reads your files automatically, or searches the live web.
  • CPublic chain, public data. The chain is permanent. Personal data belongs in the encrypted local vault, never in a public event.

03 / GET STARTED

Get started: choose what you want to run.

  1. Use RabbitOS online: open the account-free workspace. No sign-in or installation is needed. Try Qwen chat, public research, or the local brain/body explorer. Chats and notes stay in this browser; hosted AI requires consent and internet.
  2. Read or inspect a file: open research summaries or the file / corpus viewer. No installer is needed. The viewer only reads the file you select.
  3. Run Python prototypes: use the Windows or Linux setup steps here. Start with the backend; the monitor and research stack are separate components.
  4. Run the website with local AI: use the local website steps below. This is a different setup from the backend and requires Ollama.

Before using terminal commands: install Python 3.11 or 3.12 and Git, then reopen your terminal. Python 3.13/3.14 is not supported by the pinned prototype dependencies. Commands use 3.11; replace it with 3.12 if that is your installed version.

Use a new writable folder. Copy and run one step at a time; review downloaded code before execution. The old Helloworld shell-pipe installers are retired. Full component setup and verification limits · Local / hosted guide.

Python backend: Windows / PowerShell

1. Download the script into your new folder.

Invoke-WebRequest -Uri https://rabbitsoftware.io/installers/setup.py -OutFile rabbitsoftware-setup.py

2. Review the setup source and open your saved copy before continuing.

3. Check prerequisites, then prepare the backend only if the check succeeds.

py -3.11 rabbitsoftware-setup.py --check
py -3.11 rabbitsoftware-setup.py --component backend

4. After setup succeeds, use the exact loopback-only start command it prints. Open http://127.0.0.1:8000/docs after starting it; stop with Ctrl+C. This backend is not the hosted web console.

Python backend: Linux / WSL

1. Use a new folder on the Linux filesystem. Install the matching Python venv package if needed, then download.

curl -fL https://rabbitsoftware.io/installers/setup.py -o rabbitsoftware-setup.py

2. Review the setup source and your saved copy before continuing.

3. Check prerequisites, then prepare the backend only if the check succeeds.

python3.11 rabbitsoftware-setup.py --check
python3.11 rabbitsoftware-setup.py --component backend

4. Use the start command printed after success, then open http://127.0.0.1:8000/docs. Stop with Ctrl+C.

Optional monitor and research components

Replace backend with monitor or research to prepare that component instead; --component all prepares all three in a fresh destination. Setup does not start services, scan devices, register tasks, or open tunnels. Existing component folders are not overwritten: for retries, use a new --directory "my-new-folder".

Windows preparation passed for all three. Linux backend health passed; full Linux monitor/research preparation is still unverified. Preparation checks do not certify full application workflows. Read the exact verification boundaries.

Local website + Ollama AI: Windows

1. Install Ollama and keep it running on its default loopback port. Download this example model while online (about 1.9 GB).

ollama pull qwen2.5:3b

2. From a folder without an existing rabbitsoftware-cloudflare checkout, download the website source. These repairs are on the published fix/vault-coordinator-status branch, not yet merged into the default branch.

git clone --branch fix/vault-coordinator-status https://github.com/rabbitsoftware-io/rabbitsoftware-cloudflare.git
cd rabbitsoftware-cloudflare

3. Review scripts\local-site.py, then start the local website server. This does not install the Python backend.

py -3.11 scripts\local-site.py --model qwen2.5:3b --port 8788

4. Open http://127.0.0.1:8788/, open Research AI, choose Local Ollama, and approve your message. Keep the terminal and Ollama running; stop the website with Ctrl+C.

Local website + Ollama AI: Linux / WSL

Install and run Ollama inside the same Linux environment, download the model, and clone the website using steps 1-2 above. Review scripts/local-site.py, then use this command from the checkout:

python3.11 scripts/local-site.py --model qwen2.5:3b --port 8788

Open http://127.0.0.1:8788/ and choose Local Ollama in Research AI. An existing installed model can replace qwen2.5:3b. A plain static server cannot handle local AI; no hosted fallback occurs. Troubleshooting and offline limits.

Research AI destinations

Research AI offers hosted Qwen3 / Cloudflare without a local install, the existing hosted Hugging Face provider, or Local Ollama through your loopback server. Choose a provider and approve each message; hosted prompts leave your computer. Live public search remains separate.

The historical browser-agent ZIP is unavailable. Current backend and research prototypes have their own setup; they do not restore that missing package.

Browse chain entries

The browser viewer searches bundled public metadata and reads one JSON file you select. Queries and file contents stay in this tab. It does not log into a cloud account or verify blockchain consensus.

Run the website locally for offline viewing after obtaining its assets. Opening a third-party source link or hosted tool still requires internet.

No automatic vault, account, device or peer connection. Each prototype has separate prerequisites and trust boundaries; the website does not register services or expose agent credentials.

05 / LIMITS

Research tooling, not clinical software.

Genomics utilities produce candidate laboratory hypotheses; they do not diagnose, recommend treatment, or edit DNA in a body. EEG and physiology features are research prototypes, not measurements of thoughts or images.

The Rust kernel is experimental and runs in QEMU only. It does not run the Python RabbitSoftware application.

STORY / THE CHAIN

Software you can check, not just trust.

RabbitSoftware keeps sources attached to every answer, personal data on your own device, and a public record of what changed that anyone can verify, timestamped through Bitcoin. It is a tamper-evident log, not a cryptocurrency, and research tooling, not clinical software.

Answers use the two public summaries linked below and your selected AI destination: hosted Qwen3 on Cloudflare, the existing hosted Hugging Face model, or Local Ollama through your local website server. Local Ollama stays on your computer. No automatic provider fallback. Privacy policy. Research is not medical advice.

Encrypted local research record

Reconstructed feature: optional local download of inputs, outputs, source context, and request status. No uploads, training sharing, or chain publication. New recovery-format records use AES-256-GCM / PBKDF2-SHA256 (600,000 iterations). Older records and .dvault files are not supported by this rebuilt module; keep their original copies. The passphrase cannot be recovered. Opened records are read-only and are never added to hosted prompts. Model output is unverified.
