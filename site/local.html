What runs locally, and what does not

Use this website from a local checkout without uploading your files. After obtaining its static assets and optional model, these local functions need no internet: published research reading, corpus metadata search, selected-file viewing, software simulation, offline CLI demo/local lookup, and local Ollama chat. Hosted AI and live web searches still need internet. RabbitOS is account-free; it does not provide cloud account/device sync.

Run the static website on your computer

From a reviewed checkout of the website repository, run:

python -m http.server 8788 --bind 127.0.0.1 --directory site

Open http://127.0.0.1:8788/. Keep the server running while using the pages; stop with Ctrl+C. Use HTTP, not file URLs, so JavaScript modules and the local metadata asset can load. This serves files from your local checkout, not from a private vault. Python's server does not apply the Pages security headers. Do not expose it to other computers.

Optional offline AI with Ollama

Install Ollama and obtain a model while online. The example small model is qwen2.5:3b; model downloads use disk space and their own licenses. If you already have an Ollama model, select its exact installed name instead. Model output is unverified, not medical advice.

ollama pull qwen2.5:3b
python scripts/local-site.py --model qwen2.5:3b --port 8788

Use backslashes in the script path on Windows: python scripts\local-site.py --model qwen2.5:3b --port 8788. Keep Ollama listening on its default loopback port 11434. Open the local website, choose Local Ollama in Research AI, and approve each message. The server forwards only to 127.0.0.1, bypasses proxies, rejects redirects and cross-origin calls, and never falls back to hosted AI. Stop the local server with Ctrl+C. Starting it does not install an auto-start task.

A plain Python static server cannot handle local AI requests; use the local-site server for that mode. Switching destinations clears the in-tab conversation and resets consent. Existing local servers using other APIs or ports are not automatically connected; no arbitrary endpoint entry is exposed.

Local functions

  • Read published research summaries. Opening third-party citations needs internet.
  • Search the bundled public metadata or inspect a selected local JSON file. No query or file contents are sent to a remote API.
  • Download and review the offline CLI. Demo/local lookup is deterministic, not generative AI. Public corpus and signed-account CLI modes use the network.
  • Run the software-only encoding simulation.
  • Prepare the local backend, monitor and research prototypes. Setup itself needs network downloads. Optional external AI providers and research collection need internet; mock backend responses are not real AI.

Hosted and unfinished functions

  • Homepage Research AI offers separate hosted Cloudflare/Hugging Face and hosted Qwen3 / Cloudflare choices. Hosted Qwen requires no local install but sends approved prompts off-device and is usage-limited. Local Ollama still requires the local website server and your installed model; weights are not bundled. No automatic fallback occurs.
  • Live public web research uses Cloudflare, Tavily and the hosted model after consent. It cannot search an offline internet.
  • RabbitOS opens without sign-in. Notes, chats and settings stay in that browser; existing private account data remains inaccessible and is not copied by local setup.
  • The historical local browser-agent ZIP is unavailable in this deployment; no working download is claimed.
  • Encrypted-record opening on the homepage is local-only and supports the recovery format, not legacy vault formats. Creating a research-chat record requires a prior chat attempt.

A full local account/device console is still a separate, unfinished implementation; hosted email authentication and cloud sync cannot be called offline. No private files, model weights or credentials are bundled here. Local chat does not execute tools, read your files, or search the live web.
